### Task 2 — `src/lib/server/billing/perEventEscrow.ts`
- Implement `initiatePerEventEscrow`:
  - Calculate fee as `2.5%` of `agreed_fare`
  - Initiate Daraja STK push to operator's linked M-Pesa account
  - Store intent in Redis with TTL (booking ID, org ID, fare, fee, timestamp)
  - Insert a pending row into `per_event_escrow_records`
- Handle STK push errors explicitly and surface typed errors

### Task 3 — `src/routes/api/fleet/bookings/[id]/anchor-ledger/+server.ts`
- Implement `POST` handler:
  - Run `assertLedgerNotGated` server-side before any write
  - Route to `anchorBusinessReservation` on `SUBSCRIPTION` path
  - Route to `initiatePerEventEscrow` on `PER_EVENT` path
  - Return typed response shape for each path so the client can transition button state correctly
- Enforce p95 targets: `SUBSCRIPTION` < 800ms, `PER_EVENT` < 1200ms — add timing logs

### Task 4 — `src/routes/api/mpesa/callbacks/per-event-escrow/+server.ts`
- Implement `POST` callback handler:
  - Validate Daraja payload signature
  - On `ResultCode === 0`: read Redis intent → call `anchorBusinessReservation` → update `per_event_escrow_records` to `completed` → update `fleet_booking` anchor status
  - On failure: update escrow record to `failed`, log structured error
  - Ensure idempotency (check if already anchored before re-firing)

### Task 5 — `src/lib/components/fleet/LedgerAnchorButton.svelte`
