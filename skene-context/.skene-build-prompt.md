# Implement GPS Broadcast Path & Ledger Depth Flywheel

## Context
Reference @/sec/root/SHFTCCONK/skene-context/growth-plan.md for full product and business context.

We are building the GPS broadcast path and ledger depth flywheel for a Kenyan fleet compliance platform. This includes a zero-auth driver PWA, V/T instrumentation, SMS activation nudges, Hyperledger Fabric ledger writes, and a compliance-framed upgrade gate. Confidence in this execution plan: 92%.

## What We're Building

1. **Zero-auth driver PWA** — sub-200KB, 3G-tolerant, IndexedDB queue, cell tower fallback
2. **V/T ratio instrumentation** — PostHog layer with per-vehicle GPS session coverage tracking
3. **Upstash Redis delayed jobs** — Hour-4 and Hour-24 SMS nudges keyed to absence of first GPS ping
4. **Hyperledger Fabric event writer** — binds every GPS ping to a ledger transaction with trip reference
5. **Compliance-framed free tier gate** — 30-day ledger display cap with loss-aversion upgrade prompt

## Technical Tasks to Implement

### Task 1 — Driver PWA Scaffold
- Path: `/apps/driver-pwa`
- SvelteKit static adapter
- Geolocation API with IndexedDB queue that flushes on reconnect
- Set `cell_tower_fallback: true` flag when accuracy < 50m
- Target: sub-200KB bundle, < 4s load on Safaricom 3G

### Task 2 — GPS Ping Ingest Endpoint
- Path: `src/routes/api/gps/ping/+server.ts`
- Validate device token
- Write to PostgreSQL `trip_events` table
- Enqueue Hyperledger Fabric write via job queue

### Task 3 — Hyperledger Fabric Event Writer
- Path: `src/lib/server/fabric/writeTripEvent.ts`
- Map GPS ping payload to ledger transaction
- Stamp with: `vehicle_id`, `route_corridor`, `timestamp`, `accuracy_flag`
- Target: > 99.5% write success rate per ping ingested

### Task 4 — V/T Ratio Computation
- Path: `src/lib/server/analytics/vehicleCoverage.ts`
- DuckDB query over `trip_events` per vehicle per day against `expected_trip_windows`
- Emit PostHog event `vehicle_vt_ratio_updated` on each compute cycle
- Flag any vehicle with V/T ratio < 0.5 for the operator 6AM WhatsApp briefing

### Task 5 — GPS Activation Nudge Jobs
- Path: `src/lib/server/jobs/gpsActivationNudge.ts`
- Upstash Redis delayed jobs
- Enqueue at signup: fire SMS at T+4h and T+24h if no ping received for org
- Cancel both jobs on first GPS ping received

### Task 6 — Free Tier Ledger Gate UI
- Path: `src/lib/components/FreeTierLedgerGate.svelte`
- Query `ledger_event_count` and `days_until_cap`
- Render loss-aversion upgrade prompt showing trip event count and KES compliance protection estimate
- Surface at Day 28 of operator ledger display retention

### Task 7 — STK Push Upgrade Flow
- Path: `src/routes/api/billing/mpesa-upgrade/+server.ts`
- Pre-populate request with ledger stats
- Fire Daraja STK push
- Handle idempotency via Upstash Redis key scoped to `operator_id + plan_id`

## Data Triggers to Handle

| Trigger | Action |
|---|---|
| No GPS ping 4h after account creation | Fire Hour-4 SMS nudge |
| No GPS ping 24h after account creation | Fire Hour-24 compliance-framed SMS |
| First GPS ping received | Cancel nudge jobs, unlock full nav, trigger UI celebration, write ledger genesis event |
| Operator ledger retention reaches Day 28 | Surface `FreeTierLedgerGate` upgrade prompt |
| Fleet active vehicles ≥ 5 AND ledger history ≥ 60 days | Unlock Fleet Intelligence gate UI |
| V/T ratio < 0.5 for any vehicle | Flag in operator 6AM WhatsApp briefing |
