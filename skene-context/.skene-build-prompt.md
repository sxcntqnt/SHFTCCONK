# Implement Compliance Monetisation & Ledger Gate System

## Context

Reference @/sec/root/SHFTCCONK/skene-context/growth-plan.md for full product context.

We are building the **Compliance Monetisation & Ledger Gate** system with 93% confidence. This gates free-tier operators at 5 `BUSINESS_RESERVATION` anchors/month, surfaces a 2.5%-of-fare M-Pesa escrow path when quota is exceeded, and drives subscription conversion via quantified KES revenue-exposure copy.

---

## What We're Building

1. `LedgerGateStatus` computation and Redis-cached gate evaluation
2. `LedgerAnchorButton` six-state UI: `IDLE`, `LOADING`, `SUCCESS`, `ERROR`, `QUOTA_EXCEEDED`, `PER_EVENT_OFFER`
3. Per-event M-Pesa STK push escrow flow with Redis intent store and Daraja callback handler
4. Anchor-ledger API endpoint routing between `SUBSCRIPTION` and `PER_EVENT` paths
5. Inline upgrade prompt with operator-specific KES exposure figures and M-Pesa STK push initiation

---

## Technical Tasks — Implement in This Order

### 1. `src/lib/server/billing/ledgerGate.ts`

- Implement `getLedgerGateStatus(orgId: string): Promise<LedgerGateStatus>`
- Implement `assertLedgerNotGated(orgId: string, booking: FleetBooking): Promise<void>`
- Redis cache key: `ledger_gate:{orgId}` with 60s TTL
- Cache invalidation on successful anchor or tier change
- `LedgerGateStatus` shape: `{ path: 'SUBSCRIPTION' | 'PER_EVENT' | 'HARD_BLOCKED', monthlyAnchorCount: number, tierCap: number, agreedFare: number, mpesaLinked: boolean }`
- Gate resolves `PER_EVENT` when `agreed_fare > 0` AND `mpesa_account_linked`; resolves `HARD_BLOCKED` otherwise

### 2. `src/lib/server/billing/perEventEscrow.ts`

- Implement `initiatePerEventEscrow(orgId: string, bookingId: string, agreedFare: number): Promise<EscrowInitResult>`
- Calculate fee: `Math.ceil(agreedFare * 0.025)`
- Initiate Daraja STK push to operator's linked M-Pesa number
- Store intent in Redis: `per_event_escrow_intent:{checkoutRequestId}` → `{ orgId, bookingId, agreedFare, fee, initiatedAt }` with 10-minute TTL
- Insert pending row into `per_event_escrow_records` with status `PENDING`
- Return `{ checkoutRequestId, fee, phoneHint }`

### 3. `src/routes/api/fleet/bookings/[id]/anchor-ledger/+server.ts`

- `POST` handler only
- Call `assertLedgerNotGated` server-side first — throw `402` with structured error if `HARD_BLOCKED`
- Route to `anchorBusinessReservation` directly on `SUBSCRIPTION` path
- Route to `initiatePerEventEscrow` on `PER_EVENT` path, return `{ path: 'PER_EVENT', checkoutRequestId, fee }`
- p95 latency targets: `SUBSCRIPTION` < 800ms, `PER_EVENT` < 1200ms — add timing logs
- Wrap in try/catch, return typed error responses

### 4. `src/routes/api/mpesa/callbacks/per-event-escrow/+server.ts`

- `POST` handler for Daraja callback
- Read `ResultCode` from payload — only proceed if `=== 0`
- Read Redis intent by `CheckoutRequestID`
- Call `anchorBusinessReservation(bookingId, orgId)`
- Update `per_event_escrow_records` row: set `status = 'COMPLETED'`, `completed_at`, `mpesa_receipt`
- Update `fleet_bookings` to reflect anchored state
- On any failure: set escrow record `status = 'FAILED'`, log structured error, return `200` to Daraja regardless
- Target: callback → ledger anchor completion rate > 95%

### 5. `src/lib/components/fleet/LedgerAnchorButton.svelte`

- Accept props: `gateStatus: LedgerGateStatus`, `bookingId: string`, `agreedFare: number`
- Derive initial UI state from `gateStatus` via `deriveInitialState(gateStatus)` — map `SUBSCRIPTION` → `IDLE`, `PER_EVENT` → `PER_EVENT_OFFER`, `HARD_BLOCKED` → `QUOTA_EXCEEDED`
- Implement all six states with distinct copy and affordances:
  - `IDLE`: "Anchor Reservation" CTA
  - `LOADING`: spinner, disabled
  - `SUCCESS`: confirmation, green
  - `ERROR`: retry affordance, error message
  - `QUOTA_EXCEEDED`: show `monthlyAnchorCount/tierCap`, KES exposure figure, upgrade CTA
  - `PER_EVENT_OFFER`: show 2.5% fee in KES, M-Pesa STK push CTA, "or upgrade to Starter" link
- Fire `posthog.capture('ledger_anchor_state_transition', { from, to, bookingId, orgId })` on every state change
- Show inline subscription conversion prompt when `per_event fees this month > KES 1,200` — surface exact figure
- Show upgrade banner when `vt_snapshot.unverified_revenue_exposure_kes >= 2000`

### 6. `supabase/migrations/add_per_event_escrow.sql`

- Create `per_event_escrow_records` table:
  - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`
  - `org_id uuid NOT NULL REFERENCES organisations(id)`
  - `booking_id uuid NOT NULL REFERENCES fleet_bookings(id)`
  - `agreed_fare integer NOT NULL` (KES, integer pence-equivalent)
  - `fee integer NOT NULL`
  - `status text NOT NULL CHECK (status IN ('PENDING','COMPLETED','FAILED'))`
  - `checkout_request_id text NOT NULL UNIQUE`
  - `mpesa_receipt text`
  - `initiated_at timestamptz NOT NULL DEFAULT now()`
  - `completed_at timestamptz`
- Add index: `(org_id, initiated_at DESC)`
- Add `ledger_anchor_usage` monthly count query as a SQL view or function: `get_monthly_anchor_count(org_id uuid, month date) → integer` counting `BUSINESS_RESERVATION` anchors for the calendar month
